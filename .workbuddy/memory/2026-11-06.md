## 功能 8（雅思阅读训练）拟新增「已学词定制短文」
- 需求：根据目前已学习过的单词，生成一篇雅思风格短文进行学习。用户要求先给方案，并确认是否需要引入 AI。
- 现状调研：主菜单 8 → `reading_practice.ReadingPractice.run()`，子菜单 1–5；`word_study.py` 的 `reading_practice()` 会临时关闭 `CenteredStdout`。依赖只有 edge-tts / fsrs / pypdf，全项目无 LLM、无 API key 代码。阅读界面可复用 `reading_viewer.show_passage(title, body)` 与 `reading_exam.run_exam(title, body, session)`（ExamReader 继承 ConsoleReader，支持分栏 + 双击查词）。
- 词条装配：`enrich_words()` 从 `word_learn.db` 的 `VOC_TB` 批量取释义/音标；例句来自 `PR_TB`；`get_word_phrases()` 已有过滤逻辑。
- 关键数据（本次实算）：学习列表 140 词且全部 `reps>0`，复习日志 5025 条，雅思真题 211 篇。140 词中 129 个曾在真题出现，但**单篇最多只命中 15 个**（多为 evidence / despite / effect 等通用词），displace / compliment / spouse / glimpse 等 11 词从未出现 → 纯题库选篇或拼句无法按词表定制，结论是需要云端 LLM 生成。
- 建议架构：OpenAI 兼容 `/chat/completions` + `urllib` 标准库（不新增依赖），密钥走环境变量，返回严格 JSON（正文 / 目标词文中句 / 理解题），本地校验覆盖率并落库缓存；离线降级为「真题语境卡」；默认不写 FSRS，保持纯文字界面无 emoji。
- 状态：**仅给方案，尚未改任何代码**，等用户确认方案与模型接口。

## 效果样例（已产出，代码仍未改）
- 用户要求先出一篇看效果 → 新增 `data/sample_passage.json`（title / topic / target_words / body / questions，纯 JSON 无 emoji），作为后续实现的输出格式样例与测试 fixture。
- 选词策略：11 个在 211 篇真题中**零命中**的冷门词（displace / compliment / spouse / glimpse / fulfill / compel / huddle / bind / cue / magnify / crawl）+ 4 个 `is_leech=1` 顽固词（detail / fairly / contrary / fatigue）= 15 个目标词。
- 实测：正文 365 词，目标词 15/15 全覆盖；按词形还原后全文命中 **78/140** 个已学词（56%），远高于真题单篇最多 15 个。
- 实现坑（已验证）：覆盖率校验必须处理屈折变化，`magnify → magnifies` 曾被简单匹配误判为缺词；还需注意 -y→-ies、英式/美式拼写（fulfill / fulfil、judgment / judgement）。
- 演示文写成了完整 Passage 长度（365 词），正式功能默认收敛到 200–250 词并做成可配置。
